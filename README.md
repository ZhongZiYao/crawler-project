# 银行理财公告历史信息披露爬取任务 · 需求书

> 本文件只描述**要做什么任务**，不描述当前代码状态、已完成进度、踩坑记录等。新接手的人看完本文应当能立刻明白任务边界、输入、输出、业务规则、成功条件，不需要再翻历史会话。

---

## 1. 任务背景

监管要求每月初汇总上月 **22 家银行理财子公司 / 商业银行**的"历史信息披露文件"，覆盖产品说明书、发行公告、定期报告、临时性信息披露、到期公告、公司公告等六大类公告类型。原始数据来源为各机构官网 / 资讯披露平台，每个机构各自独立。

交付物本质上是按**发行机构**维度组织的、按**业务分类**打标签的 PDF / Office 文件集合，由业务侧接收。

### 2.2 目标

1. **按日期区间增量下载**：每个机构有其"上一批次截止日期"（E:\Program Files\PythonProject\crawler project\zzy_crawler\project_meta.py文件给出了start_date），只下载 `start_date ≤ date ≤ today` 之间的公告
2. **批量调度**：跑一条命令调度全部 22 个项目，顺序执行，每个项目跑完自动接力下一个
3. **日志与可恢复**：每个项目有独立下载日志、运行日志；支持断点续跑（已下载的唯一 key 跳过）
4. **业务分类**：下载完后按业务规则将全部下载文件归类到 3 大类（产品说明书 & 发行公告 / 定期报告 / 临时性信息披露），输出到 `分类结果/`
5. **可重跑**：失败可手动重跑，重复文件自动跳过；不存在误删已有数据

## 3. 输入

### 3.1 输入文件（目录根）

| 文件名 | 作用 |
| --- | --- |
| `历史信息披露文件下载规则.docx` | 业务分类规则主文档，定义 3 大类公告的归类标准 |
| `产品说明书&发行公告.xlsx` | 上批次截止日参照表，用于推断各机构 `start_date` |
| `定期报告-临时报告0430.xlsx` | 定期报告 / 临时报告截止日参照 |
| `定期报告-六家手工下载.xlsx` | 6 家手工下载的定期报告参照（部分项目源数据从此推日期）|
| `1.txt` ~ `5.txt` | 5 组"临时性信息披露"关键字规则，多组并集取并集 |

### 3.2 已存在的代码与目录

- 22 个项目目录已经在 `crawler project/c01-c08/` 下，每个目录下：
  - 项目级 `main.py`（每个机构一套，已经针对其网站实现过登录 / 分页 / 下载逻辑）
  - 项目级 `.venv-<id>/`（已在项目内的独立虚拟环境）
  - `project_meta.py`：备用元数据

### 3.3 起始日期

每个项目有各自独立的 `start_date`。默认 `end_date = today`（执行命令当天）。`end_date` 可通过命令行参数覆盖。
